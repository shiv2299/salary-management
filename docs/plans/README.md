# Redesign Plans

The working spec and plans the UI/UX redesign was built from, kept as a record of how the work was broken down and handed to AI agents. They were written before each phase and are not updated since: where they differ from the code or from `docs/requirements.md`, `docs/spec.md`, `docs/architecture.md`, `docs/design.md` or `docs/decisions.md`, those documents win. A plan that calls itself "binding" was binding only while its phase was being built.

| File | What it is |
|---|---|
| `2026-10-21-ui-ux-redesign-design.md` | The redesign spec, brainstormed and agreed before any plan. |
| `2026-10-21-ui-ux-redesign.md` | The overview: four phases, each shippable on its own, and the interfaces between them. |
| `2026-10-21-redesign-phase-1-style-and-employees.md` | Phase 1: visual style and the employee list. |
| `2026-10-21-redesign-phase-2-bulk-revision.md` | Phase 2: the bulk salary revision screen. |
| `2026-10-22-redesign-phase-3-seed-and-history.md` | Phase 3: the fuller seed, the reset command and the salary history chart. |
| `2026-10-21-redesign-phase-4-insights.md` | Phase 4: the insights rebuild and attention filters. |

Each phase plan was written just before its phase started, so it is grounded in the code the previous phase left behind. How the plans were executed and checked is in `docs/ai-workflow.md`.
